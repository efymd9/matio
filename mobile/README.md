# Matio — mobile app (Expo / React Native)

iOS + Android client for matio.tv. Plan, decisions and phasing live in
[`../docs/mobile-app-plan.md`](../docs/mobile-app-plan.md) — read that first.

## Why this directory is not a workspace package

`mobile/` is deliberately **outside** the repo's pnpm workspace and installs with **npm**
(`mobile/package-lock.json`, `mobile/node_modules`). Expo needs `node-linker=hoisted` to work
under pnpm, which would change the *web* app's install semantics, and this repo has a history
of pnpm shared-store corruption. Keeping the two package managers separate means an app install
can never break a web build. See `docs/mobile-app-plan.md` §3.

Consequences, both handled in `metro.config.js`:

- `config.watchFolders` includes `../lib` so the shared modules resolve.
- `config.resolver.disableHierarchicalLookup = true` stops Metro walking up and finding the
  web app's `react` at the repo root, which would bundle two copies of React.

## Shared code

The app imports a few genuinely universal modules straight from the web app's `lib/`:

| App module | Re-exports | Why shared |
|---|---|---|
| `src/shared/design.ts` | `../../../lib/design` | brand tokens — colours must not drift between surfaces |
| `src/shared/api-types.ts` | `../../../lib/api/types` | the `/api/v1` wire contract, so a DTO change fails compilation instead of failing on a user's phone |

Those two files are the **only** places holding a path across the project boundary. Import
`@/shared/...` everywhere else. Do not extend this to modules that aren't universal — anything
importing `server-only`, `next/*`, or drizzle will break the bundle.

## Running it

The app needs the web app's `/api/v1` endpoints, which are not yet deployed to production. So
in development, run **both**:

```bash
# terminal 1 — repo root: the API
pnpm dev --port 3100

# terminal 2 — here: Metro
npx expo start
```

Then launch on the simulator. **Do not pass `--ios`** if automation permissions are unavailable
(see gotchas); open it directly instead:

```bash
xcrun simctl boot "iPhone 16 Pro"
xcrun simctl openurl booted "exp://127.0.0.1:8081"
```

For a native dev build (required once `react-native-video`, Cast, or any other custom native
module lands):

```bash
npx expo run:ios --device "iPhone 16 Pro"
```

### API base URL

Resolution order in `src/api/client.ts`:

1. `EXPO_PUBLIC_API_BASE_URL` if set
2. `http://localhost:3100` in dev
3. `https://matio.tv` in release builds

A **physical device cannot reach the Mac's `localhost`.** Use the LAN IP:

```bash
EXPO_PUBLIC_API_BASE_URL=http://192.168.0.125:3100 npx expo start
```

## Gotchas found so far

- **macOS Automation (TCC) permission.** If the shell running Expo lacks permission to control
  System Events, `expo start --ios` crashes with
  `osascript … "System Events" … exited with non-zero code: 1` — it happens when the CLI tries
  to *activate the Simulator window*, not while bundling. Run `npx expo start` without `--ios`
  and open the URL with `simctl` instead.
- **Expo Go's first-run dev-menu sheet** covers the lower half of the screen and needs a real
  tap to dismiss; `simctl` cannot tap. A native dev build has no such sheet.
- `/ios` and `/android` are gitignored — they are generated by prebuild, never edited by hand.

## Not yet added (deliberately)

Two dependencies are wanted for real design fidelity and are **pending approval** (the repo's
convention is to ask before adding):

- `expo-linear-gradient` — the brand is built on gradients (hero scrims, gold CTAs, the duotone
  wash, tone fallbacks). `src/components/ui.tsx` currently fakes vertical scrims with stacked
  opacity bands and flattens the duotone to a solid tint.
- `@expo-google-fonts/anton` (+ Geist) — Anton is the display face for every heading. Display
  type currently approximates it with the heaviest system weight plus the spec's uppercase and
  tracking. Swap `fontFamily` into `display` in `src/theme.ts`; no call sites change.
