# Этап 08 — Автопилот рутины (этап зрелости)

## Что вы получите

Основная сессия превращается в дежурного диспетчера: два persistent-вотчера
(очередь PR + issues) будят её на каждое событие, хук-гарды не дают
завершить ход с мёртвым вотчером, а задачи с лейблом `auto` (баги и
техдолг без UI и продуктовых решений) она исполняет САМА — суб-агентами в
изолированных worktree, с капом слотов и правилом непересечения файлов.
Уборщик worktree удаляет только механически доказанное «всё влито».
Владелец запускает руками только эпики и всё видимое/продуктовое/платное.

**Пререквизиты**: этапы 01–03 обкатаны (замкнутый PR-цикл работает,
CI — ворота мержа), у вас есть опыт хотя бы десятка PR через процесс.
Автопилот усиливает работающий процесс; сломанный он усилит тоже.

## Что делает человек

1. Честно оцените зрелость: были ли за последнюю неделю PR, влитые мимо
   ревью? Есть ли задачи без issue? Если да — сначала почините это.
2. Согласуйте с собой скоуп `auto` (ниже) — и потом не расширяйте его
   в моменте «ну это же мелочь».
3. Скормите промпт агенту в ОСНОВНОМ чекауте (не в worktree).

## Промпт для агента

```
Внедри автопилот рутины по плейбуку docs/mega-process/ (этап 08).
Скрипты — из docs/mega-process/tools/, копировать ЦЕЛИКОМ с комментариями
(в них конструктивные решения — канон «не переписывать по памяти»).
Работай веткой + PR; один файл ставится вне git (см. п. 3).

1. Вотчеры основной сессии в tools/claude/: pr_watcher.sh (очередь PR:
   новые, красные чеки не нужны — их видит бебиситер владельца PR,
   отставание behind, мержи) и issue_watcher.sh (новые issues и смена
   триаж-флагов auto/spec:ready/needs:owner). bash -n обоих. chmod +x.
2. Гард вотчеров: tools/claude/watcher_guard.sh из комплекта.
3. Хуки основной сессии: содержимое docs/mega-process/tools/
   settings.local.main.json → в .claude/settings.local.json ОСНОВНОГО
   чекаута (файл gitignored — он не должен приезжать в worktree агентов;
   проверь, что .gitignore закрывает .claude/settings.local.json, иначе
   добавь). Удали ключи-комментарии «_». Если файл уже существует — слей
   секции hooks.
4. Уборщик: tools/claude/wt_janitor.py из комплекта (удаляет worktree
   только при доказанном «копия чиста + tip ветки внутри ВЛИТОГО PR»;
   политика — в докстринге, не ослаблять).
5. Скилл /duty: если он установлен с этапа 02 — сними из него и из
   /review пометку «вотчеры приезжают на этапе 08» (теперь они боевые) и
   сверь пути и кап слотов с CLAUDE.md; если нет — скопируй
   docs/mega-process/skills/duty/SKILL.md в .claude/skills/duty/SKILL.md,
   заменив {{PROJECT}}.
6. CLAUDE.md — раздел «Автопилот рутины (лейбл auto)»:
   - что это: задачи с лейблом auto основная сессия исполняет сама —
     суб-агентом (Agent tool, isolation: "worktree"), каждому свой worktree;
   - кому можно auto: type:bug и type:debt БЕЗ новых/изменённых элементов
     интерфейса. НИКОГДА не auto: видимый UI, продуктовые решения, платные
     действия, снос стендов/данных, Release PR. p1 — можно, но с
     немедленным докладом владельцу о запуске;
   - кто вешает лейбл: основная сессия при триаже; рабочий агент — при
     создании попутного бага, если рутинность очевидна. Сомнение = не вешать;
   - кап слотов: 2 одновременно (слоты не «помнятся», а вычисляются с
     доски: auto ∧ In progress); слот заполняется только задачей без
     пересечения файлов/модулей с активными;
   - суб-агенту в промпт: работа по спеке, PR с Closes #N, НЕ бебисить
     (конвейер у основной сессии), грабли голого worktree (gitignored-файлы
     копировать из основного чекаута);
   - ГРАБЛЯ «спящий суб-агент»: суб-агент, от которого долго нет ни PR,
     ни вопросов, мог молча встать на развилке — пинг SendMessage
     «где ты?», не ждать;
   - замечания ревью суб-агенту — SendMessage тому же агенту (его
     контекст жив), не новый агент.
7. Проверка живьём:
   - заведи безобидную тех-задачу (например, опечатка в доке), поставь
     auto + spec:ready (спека по /spec), доска tech;
   - стартовый ритуал /duty: взведи оба вотчера инструментом Monitor
     (persistent: true; НЕ Bash run_in_background, НЕ «&»);
   - продиспетчеризуй задачу суб-агентом в worktree, доведи PR по
     конвейеру (ревью по /review, мерж, доска Done), прогони
     python3 tools/claude/wt_janitor.py --yes и покажи мне весь цикл
     одним отчётом.
```

## Критерии готовности

- [ ] Новая сессия в основном чекауте: SessionStart-хук напоминает про
      вотчеры; попытка завершить ход с мёртвым вотчером блокируется
      Stop-хуком.
- [ ] Событие в очереди PR (новый PR/мерж/behind) будит основную сессию
      строкой БЫЛО/СТАЛО без перевзвода вотчера.
- [ ] Тестовая auto-задача прошла полный цикл без ручных сообщений
      владельца: триаж → спека → суб-агент → PR → ревью → мерж → Done →
      janitor убрал worktree.
- [ ] `wt_janitor.py` без `--yes` показывает честный dry-run и пропускает
      запертые/грязные/невлитые worktree.

## Бюджетные развилки

- **Эконом**: сам автопилот бесплатен, но суб-агенты жгут токены подписки
  Claude заметно быстрее — на Pro-плане реалистичен кап 1–2 слота и
  выборочность в auto-лейблах. Начните с капа 2.
- **Как у оригинала**: кап 3 (поднят с 2 после недель обкатки; качество
  держат два инварианта: мержи всё равно последовательны через основную
  сессию, а дополнительный слот заполняется только задачей без пересечения
  файлов). Ситуативный кап 4 — только на «веере» из ≥4 доказанно
  независимых задач; на цепочках зависимостей лишний слот пустует, а
  каскад behind и очередь ревью растут зря. Триггер повышения капа: слоты
  стабильно заняты, ревью не захлёбывается, ни одного инцидента
  пересечения за неделю.
