# Быстрый старт: один промпт — и агент разворачивает процесс сам

Как пользоваться (всё остальное сделает агент):

1. Скопируйте каталог `mega-process/` в свой репозиторий как
   `docs/mega-process/` (если читаете это — вероятно, уже скопировали).
2. Откройте Claude Code в корне репозитория.
3. Вставьте промпт ниже целиком — одним сообщением, без правок.

Агент прочитает плейбук, заведёт внедрение как задачи в вашем же трекере
и поведёт вас по этапам 01–05, объясняя по дороге, зачем каждый шаг.
От вас понадобятся: аккаунт GitHub, ~1–2 часа на первые этапы (частями),
на этапе 05 — карта для Fly.io (эконом-режим ~$3–10/мес). Каждое платное
действие агент явно согласует.

## Промпт (скопируйте всё из блока)

```text
Ты разворачиваешь в этом репозитории «мега-процесс» — проверенный на
живом продукте процесс разработки для связки «человек-владелец + агенты
Claude Code». Полный плейбук лежит в docs/mega-process/. Твоя роль —
проводник: техническую работу делаешь ты, но ведёшь владельца по шагам,
где нужен человек, и ПО ХОДУ объясняешь простым языком, зачем каждый шаг
и как процесс будет работать в итоге. Владелец должен ПОНИМАТЬ систему,
которую получает, а не слепо выполнять команды. Обучающий тон, без
снисходительности; жаргон — только с расшифровкой при первом упоминании.

ШАГ 0 — подготовка (до любых изменений):
1. Прочитай ВЕСЬ плейбук: docs/mega-process/00-overview.md, все файлы
   этапов 01–10, docs/mega-process/tools/README.md и каждый SKILL.md в
   docs/mega-process/skills/. Скрипты из tools/ читай целиком в момент
   установки — их комментарии входят в канон процесса.
2. Осмотри репозиторий: есть ли код, какой стек, настроен ли git-remote
   на GitHub. Спроси у владельца недостающее: название продукта, стек
   сервера и мобильного приложения (если кода ещё нет), под каким
   GitHub-аккаунтом работаем. Репозиторий ещё не на GitHub — помоги
   создать и запушить (gh repo create).
3. Проверь инструменты: git, gh (авторизация: gh auth status; понадобится
   скоуп project — gh auth refresh -s project), jq. Чего-то нет — дай
   владельцу команды установки (они перечислены в этапе 01) и дождись.
4. Расскажи владельцу в 5–7 предложениях, как будет выглядеть работа
   после внедрения (замкнутый PR-цикл, доска как единый источник правды,
   живые документы-скиллы — материал в 00-overview.md), и что сейчас вы
   пройдёте этапы 01–05, а 06–10 подключите позже по потребности.

ШАГ 1 — этап 01 и самозагрузка трекера:
1. Пройди этап 01 (docs/mega-process/01-github-foundation.md): раздел
   «Промпт для агента» этого файла — твоя инструкция; все «спроси у
   меня» адресуй владельцу; перед изменениями на GitHub покажи план.
2. Как только появятся лейблы и доска — оформи само внедрение процесса
   как ПЯТЬ задач в новорождённом трекере, по одной на этапы 01–05:
   заголовок «Мега-процесс, этап NN: <название этапа>», тело — ссылка на
   файл этапа и его раздел «Критерии готовности» как критерии приёмки,
   лейблы type:feature + domain:infra + p1 + by:claude-code (авторский
   лейбл основной сессии — а это ты). Каждую добавь на доску
   (gh project item-add — этап 01 объясняет, почему gh issue create на
   доску НЕ добавляет). Задачу этапа 01 сразу переведи в Done — она
   только что выполнена: это первая запись в летописи проекта и живая
   демонстрация механики доски (ID поля Status и опций у тебя уже на
   руках после настройки доски). Задачу этапа 02 поставь In progress.
3. Покажи владельцу доску и проговори: с этой минуты процесс ведёт сам
   себя — внедрение оставшихся этапов трекается как обычные задачи, и
   всё дальнейшее владелец сможет видеть на этой доске.

ШАГ 2 — этапы 02, 03, 04 (UI Lab), 05 (деплой) по очереди; для каждого
один и тот же ритуал:
1. ОБЪЯСНИ: что этап даст и почему он именно на этом месте лестницы —
   2–4 абзаца простым языком (материал: разделы «Что вы получите» и
   «Бюджетные развилки» файла этапа). Бюджетные развилки — решения
   владельца: покажи эконом-вариант и «как у оригинала», дай свою
   рекомендацию для его случая и спроси, как делаем.
2. ЗАПРОСИ его часть — раздел «Что делает человек»: перечисли конкретные
   действия (регистрации, токены с точными скоупами, клики в UI
   вендоров) и объясни, зачем каждое. Жди выполнения, помогай при
   затыках; ничего не имитируй за него.
3. ИСПОЛНИ «Промпт для агента» этапа как свою инструкцию. С этапа 02 и
   далее работай по правилам, которые сам же установил: ветка от
   origin/main → PR → доска; свои PR по этим внедренческим задачам
   мержишь ты (ты и есть основная сессия этого репозитория).
4. ПРОВЕРЬ «Критерии готовности» вместе с владельцем: каждый пункт —
   командой или действием, не на веру. Не сходится — чини до зелёного,
   прежде чем идти дальше.
5. ЗАКРОЙ задачу этапа на доске (с этапа 02 — через
   tools/claude/board_status.sh), переведи следующую в In progress и
   подведи итог в 2–3 предложениях: что нового появилось в процессе и
   как владельцу этим пользоваться.

Особый случай — пустой репозиторий: если после этапа 02 в репо ещё нет
кода, предложи владельцу создать минимальные скелеты сервера и
приложения под выбранный стек (сервер с /healthz и одним тестом,
приложение с одним экраном и одним тестом) — отдельной задачей через
только что построенный процесс: issue → доска → ветка → PR → ревью →
мерж. Это первая боевая обкатка замкнутого PR-цикла, и этапам 03–05
нужно, чтобы линтерам, тестам и деплою было на чем работать.

ПРАВИЛА ПО ДОРОГЕ:
- Один этап за раз; следующий не начинай без явного «поехали» владельца.
- Секреты — только в предназначенные места (gh secret set, секреты
  хостинга, менеджер паролей владельца); никогда — в файлы репо; в чат —
  только когда без этого не обойтись, и сразу предупреждай об этом.
- Платные действия (привязка карты, платные планы, машины) — только с
  явного согласия владельца и с названной ценой.
- Наткнулся на противоречие в плейбуке или нехватку данных — скажи
  честно и спроси; молча не импровизируй.
- Если сессия прервётся — продолжение всегда видно на доске: найди
  задачу «Мега-процесс, этап NN» в In progress и продолжай её ритуал.

ФИНАЛ (после зелёных критериев этапа 05): поздравь владельца — ядро
процесса работает: агенты гонят задачи через PR-цикл, CI держит
качество, UI утверждается вживую через Lab, мержи сами едут на staging.
Покажи итоговую картину и расскажи по одному предложению про оставшиеся
этапы: 06 (данные и бэкапы с restore-пробой) и 07 (наблюдаемость)
довершают ядро, 08 (автопилот рутины), 09 (нагрузочное) и 10 (GDPR) —
модули зрелости. Предложи завести задачи на этапы 06–07 в бэклог прямо
сейчас — командой из процесса; про 08–10 — вернуться, когда дозреют.

Начинай с шага 0.
```
