# Этап 04 — UI Lab: стенд, токены, Lab-first

## Что вы получите

Отдельный UI-стенд приложения (галерея компонентов и экранов с живыми
ручками, без сети) и ритуал **Lab-first**: новый элемент интерфейса сначала
появляется в стенде минимум в пяти вариантах, владелец выбирает вживую на
устройстве, и только утверждённый вариант едет в код. Плюс токены
дизайн-системы с механическим запретом «магии» в фичах и скриншот-тесты
(голдены), ловящие визуальные регрессии.

## Что делает человек

1. Решите, на каком устройстве смотрите стенды (телефон/эмулятор) — это
   ваша часть ритуала: агент не имеет права утверждать UI сам.
2. Примите правило и держите его: **не описывайте агенту «сделай красиво»
   в бою** — просите стенд с вариантами. Выбор варианта — минута вашего
   времени, зато итерации не жгут основной код.
3. Скормите промпт.

## Промпт для агента

```
Настрой UI-инфраструктуру по плейбуку docs/mega-process/ (этап 04).
Стек приложения возьми из репо; примеры даны для Flutter — адаптируй
(React Native: Storybook + отдельная entry; нативные: свой prototype-таргет).
Работай веткой + PR.

1. Токены дизайн-системы: каталог ядра (пример Flutter: lib/core/theme —
   цвета, типографика, отступы, радиусы; lib/core/ui — базовые
   компоненты). Все значения — из токенов; фичи импортируют токены и
   компоненты ядра, не сырые стили.
2. Механический запрет «магии» в фичах — шаг в app-ci (этап 03), по
   образцу оригинала (grep-чек: в каталоге фич запрещены прямые
   Colors.* / TextStyle( / EdgeInsets. / Color(0x — адаптируй паттерны под
   стек). Красный шаг называет файл и строку.
3. UI-стенд (галерея): отдельный entrypoint, собирается отдельным
   флейвором/таргетом с отдельным bundle id (ставится РЯДОМ с основным
   приложением). Внутри: каталог экранов-демо всех ключевых компонентов,
   живые ручки (переключение темы, размеров, состояний), БЕЗ сети и
   реального бекенда. Стенд исключается из подсчёта покрытия (см.
   tools/qa/mobile_coverage.py с этапа 03 — там уже есть исключение
   каталога галереи; сверь пути).
4. Голдены/скриншот-тесты ключевых компонентов и экранов в фиксированных
   состояниях. При падении — CI выкладывает диффы артефактом (upload-artifact
   с if: failure()). Если рендер платформозависим — генерация эталонов в
   docker-контейнере, одинаковом локально и в CI.
5. CLAUDE.md — раздел «UI»:
   - UI только через токены: в фичах запрещены прямые стили (см. CI-чек);
   - Lab-first: новый/изменённый видимый элемент UI СНАЧАЛА в стенд,
     минимум 5 РАЗНЫХ вариантов (не вариации одного), НЕ копировать
     референс пиксель-в-пиксель; владелец смотрит вживую на устройстве и
     утверждает; только потом реализация в основном коде; выбранные
     значения фиксируются в токенах и в спеке задачи;
   - голдены обновляются осознанно (команда обновления + просмотр диффа),
     а не «перегенерил, чтобы CI позеленел».
   В скилле /review с пункта «UI-токены» сними пометку «(после этапа
   04)» — он теперь боевой.
6. Демонстрация: собери стенд, поставь на устройство/эмулятор, покажи мне
   как запустить. Прогони голдены и grep-чек локально.
```

## Критерии готовности

- [ ] Стенд собирается и ставится рядом с основным приложением; работает
      без сети.
- [ ] PR с прямым стилем в фичах падает на grep-чеке CI.
- [ ] Голдены бегут в CI; намеренная порча компонента даёт красный тест с
      диффом-артефактом.
- [ ] Первый реальный ритуал пройден: агент выкатил ≥5 вариантов нового
      элемента в стенд, вы выбрали вживую, вариант уехал в токены и код.
- [ ] Правила Lab-first и токенов — в CLAUDE.md; /review проверяет
      «UI-токены» в чеклисте диффа.

## Бюджетные развилки

- **Эконом**: всё в этом этапе бесплатно — это дисциплина, не сервисы.
  Минимальный вариант без отдельного флейвора: галерея как скрытый экран
  dev-сборки (хуже: стенд нельзя поставить рядом с основным приложением).
- **Как у оригинала**: отдельный gallery-флейвор с собственным bundle id +
  выделенное физическое устройство для живых утверждений + правило
  «устройство принадлежит одному инстансу, остальным эмулятор». Плюс
  дизайн-система в внешнем инструменте с синхронизацией токенов в код —
  оправдано, когда дизайн становится продуктовой ценностью, а не оформлением.
- Голдены в docker — заводите при первом же «у меня локально голдены
  другие»: расхождение шрифтов/рендера между macOS и Linux-CI — не баг
  ваших тестов, а свойство мира.
