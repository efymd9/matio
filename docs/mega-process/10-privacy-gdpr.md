# Этап 10 — Privacy/GDPR-процесс (опциональный модуль)

## Что вы получите

Инженерный privacy-процесс, встроенный в каждодневную работу: карту
персональных данных (что где живёт, сколько, как стирается), чеклист
«новая фича → обязательства», прогоняемый в каждом PR с данными, таблицу
процессоров с DPA-статусами и обязательную GDPR-строку в каждой спеке.
Модуль обязателен, если продукт обрабатывает данные пользователей из
ЕС/ЕЭЗ; полезен как дисциплина минимизации данных в любом случае.

**Это не юридическая консультация**: модуль закрывает инженерную сторону
(данные не размножаются бесконтрольно, стирание реально стирает, логи
чисты). Правовые основания, тексты согласий, DPIA и приёмку запуска
делает человек с юристом.

## Что делает человек

1. Ответьте себе на три вопроса (они определят строгость): есть ли в
   продукте чувствительные данные (ст. 9 — здоровье, интимное; учтите:
   ИИ-инференс по обычным данным тоже считается); есть ли ИИ-обработка
   контента пользователей; будут ли пользователи из ЕС.
2. Запланируйте юриста на момент публичного запуска (DPIA, политика,
   согласия) — до запуска инженерного процесса хватает.
3. Скормите промпт.

## Промпт для агента

```
Внедри privacy/GDPR-процесс по плейбуку docs/mega-process/ (этап 10).
Работай веткой + PR.

1. Скилл: скопируй ШАБЛОН docs/mega-process/skills/gdpr/SKILL.md в
   .claude/skills/gdpr/SKILL.md, замени {{PROJECT}}. Раздел «Правовая
   рамка» заполни ЧЕРНОВИКОМ по вопросам из комментария шаблона и нашему
   продукту, пометив весь раздел «черновик до ревью юристом» — реши со
   мной спорные пункты.
2. references/data-map.md (рядом со скиллом): карта данных ПО ФАКТУ
   кодовой базы — пройди модели/схемы/кеш-ключи/внешние вызовы и заполни:
   - «Где физически живут данные»: таблица хранилище → регион →
     категории данных → ретеншен (включая бэкапы с этапа 06 и устройство
     пользователя);
   - таблицы по чувствительности (обычные / чувствительные);
   - «Что уходит во внешние сервисы» (LLM-промпты, пуши, письма —
     дословно какие поля);
   - «Дыры» — честный список мест, где стирание/ретеншен ещё не
     реализованы (+ строки в docs/registry.md).
3. references/processors.md: таблица внешних сервисов, которые видят
   данные (хостинг, LLM-провайдеры, почта, пуши, трекер ошибок):
   что видит → регион → статус DPA → механизм трансфера (DPF/SCC).
   Статусы DPA сверь по публичным страницам вендоров, дату сверки укажи.
4. Правило в CLAUDE.md: любой PR, трогающий персональные данные (новое
   поле/таблица/кеш-ключ, внешний сервис, LLM-промпты, пуши/письма,
   логи) → прогнать чеклист /gdpr, карту и процессоров обновить ТЕМ ЖЕ PR.
5. Скилл /spec: добавь стандарт «GDPR-строка — обязательный финал каждой
   спеки»: перед spec:ready спека прогоняется через чеклист /gdpr, в
   конце — строка «GDPR: не применимо (данных не трогает)» либо «GDPR:
   применимо — учтено в пунктах …». Скилл /review: с пункта «Данные» в
   чеклисте диффа сними пометку «(после этапа 10)» — он теперь боевой.
6. Канон стирания: проверь фактическое поведение удаления аккаунта
   (каскады FK, кеш, файлы/медиа, джобы) и опиши в скилле; расхождения —
   в issues (type:debt, domain:backend), не чинить молча в этом PR.
7. Покажи мне: заполненную карту, таблицу процессоров, список заведённых
   issues-дыр.
```

## Критерии готовности

- [ ] Карта данных отражает реальную схему БД/кеша/внешних потоков
      (выборочная проверка: возьмите две таблицы и найдите их в карте).
- [ ] Таблица процессоров заполнена, у каждого — статус DPA и дата сверки.
- [ ] Новая спека без строки «GDPR: …» не получает spec:ready (правило в
      /spec); /review содержит пункт «Данные».
- [ ] Дыры стирания/ретеншена — в issues и docs/registry.md, а не в
      памяти.
- [ ] Черновик «правовой рамки» существует и помечен как требующий юриста.

## Бюджетные развилки

- **Эконом**: весь модуль бесплатен — это дисциплина и документы. Дешевле
  всего он обходится, если внедрён ДО накопления данных: ретеншен и
  каскады, спроектированные сразу, стоят ноль; ретрофит по живой базе —
  недели.
- **Как у оригинала**: то же + правовая рамка, проработанная с опорой на
  конкретные решения регуляторов по своей нише, DPIA перед публичным
  запуском, ZDR-режимы у LLM-провайдеров (данные API не хранятся), регион
  данных EU у всех вендоров, где он выбирается (Sentry — этап 07,
  R2-бакеты с jurisdiction=eu). Юрист — обязательная строка бюджета
  публичного запуска, не опция.
- Триггеры «зови юриста» перечислены в скилле — они срабатывают редко,
  но игнорировать их дорого (прецеденты штрафов за ИИ-сервисы без
  правового основания и возрастной проверки — миллионы евро).
