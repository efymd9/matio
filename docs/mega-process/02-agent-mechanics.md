# Этап 02 — Агентная механика: замкнутый PR-цикл

## Что вы получите

Ядро процесса: команда «Делай #N» становится самодостаточной. Агент сам
читает спеку, ведёт задачу по доске, открывает PR и **бебиситит его до
мержа** (вотчер будит его на красный CI, комментарии ревью и конфликты;
Stop-хук физически не даёт бросить открытый PR). Появляются скиллы ядра
(duty/spec/review), скрипт доски, параллельная работа нескольких агентов
в git-worktree и общая память между ними.

## Что делает человек

1. Убедитесь, что этап 01 пройден: у вас на руках PROJECT_ID, FIELD_ID и
   шесть ID опций статуса доски.
2. Решите, где живёт **основной чекаут** — каталог, в котором будет
   работать «основная сессия» (вы + Claude Code, который мержит).
   Worktree-агенты будут создаваться командой `claude --worktree <имя>`.
3. Прочитайте в `00-overview.md` карту ролей — с этого этапа вы
   перестаёте передавать сообщения между агентами: всё через тред PR.
4. Скормите промпт агенту в основном чекауте.

## Промпт для агента

```
Установи агентную механику процесса по плейбуку docs/mega-process/
(этап 02). Источники: docs/mega-process/tools/ и docs/mega-process/skills/.
Работай веткой от origin/main и одним PR.

1. Скрипты — скопируй из docs/mega-process/tools/ в tools/claude/ БЕЗ
   упрощения комментариев (в них задокументированы конструктивные решения —
   это канон процесса):
   - board_status.sh; рядом создай tools/claude/board.env, заполнив
     BOARD_OWNER, BOARD_NUMBER, PROJECT_ID, FIELD_ID, OPT_BACKLOG,
     OPT_TECH, OPT_SPEC, OPT_PROGRESS, OPT_REVIEW, OPT_DONE реальными
     значениями нашей доски (спроси у меня, если этап 01 их не оставил;
     добыть заново: gh api graphql по projectV2 → поле Status → options).
   - pr_babysit.sh, babysit_guard.sh — вотчер бебиситинга PR и его хук-гард.
   - link_shared_memory.py — подставь в {{MAIN_CHECKOUT}} абсолютный путь
     текущего (основного) чекаута.
   Всем .sh — chmod +x. Проверь синтаксис: bash -n каждого, python3 -m
   py_compile для .py.
2. Хуки: скопируй docs/mega-process/tools/settings.worktree.json в
   .claude/settings.json (коммитится; удали ключи-комментарии,
   начинающиеся с «_»; если .claude/settings.json уже существует —
   аккуратно слей секции hooks, ничего не потеряв).
3. Скиллы: скопируй docs/mega-process/skills/{duty,spec,review}/SKILL.md в
   .claude/skills/<имя>/SKILL.md, заменив {{PROJECT}} на название нашего
   продукта. Прочитай их и убедись, что ссылки на пути (tools/claude/...)
   совпадают с тем, что ты установил. Скиллы упоминают инструменты будущих
   этапов (pr_watcher/issue_watcher/wt_janitor — этап 08, gen_api.sh —
   этап 03): добавь в начало duty и review строку-пометку «вотчеры
   основной сессии и janitor приезжают на этапе 08 плейбука; до тех пор
   их роль исполняется вручную (периодический gh pr list)» — этап 08 её
   снимет.
4. CLAUDE.md — добавь разделы (сверь формулировки со скиллами, чтобы не
   разошлись):
   «Замкнутый PR-цикл»: команда «Делай #N» самодостаточна — gh issue view N
   (только spec:ready; спеки нет — стоп и коммент в issue), сразу
   tools/claude/board_status.sh N progress, ветка от origin/main,
   вертикаль по спеке, PR с Closes #N; тело PR — единственный канал к
   ревьюеру (что сделано и почему, как проверено — команды/прогоны,
   соответствие критериям приёмки по пунктам, что отложено + строки
   реестра); обратный канал — тред PR, а не issue; бебиситинг своего PR
   обязателен: вотчер tools/claude/pr_babysit.sh инструментом Monitor
   (persistent: true), НЕ через Bash run_in_background и НЕ через «&»;
   красный CI → чинит, коммент ревью → исправляет и пушит сразу + отвечает
   в треде, конфликт/отставание → git fetch && git merge origin/main + пуш,
   MERGED → ритуал уборки; осознанная пауза — файл .claude/babysit-paused;
   мерж — только основная сессия, авто-мерж взводит только она после ревью.
   «Параллельные инстансы (git worktrees)»: одна ветка = один PR; новая
   ветка всегда git fetch && git checkout -b feat/<слаг> origin/main;
   после мержа в ту же ветку не коммитить (squash её «сжёг»); конфликт с
   main разрешает пришедший вторым у себя (генерённые файлы не мержить
   руками — перегенерировать); горячие общие точки (контракт и генерённый
   клиент, тема/токены, локали, CLAUDE.md) правит один инстанс за раз;
   чужие worktree не трогать; голый worktree не содержит gitignored-файлов
   — копировать из основного чекаута, не выдумывать; записи в общую
   память — маленькие и аддитивные.
   «Трекер задач» (дополнить): обязательная пара команд
   gh issue create … --label "…" + tools/claude/board_status.sh N backlog
   (create НЕ добавляет на доску); найденный по пути баг — не чинить
   молча, а завести issue с лейблами.
5. Проверка живьём (сделай и покажи вывод):
   - создай тестовую issue, прогони board_status.sh по всем шести
     статусам, убедись на доске, закрой issue;
   - запусти bash tools/claude/pr_babysit.sh в ветке без PR — он должен
     честно отказаться («PR не найден»);
   - объясни мне в две строки, как проверить Stop-хук после первого
     реального PR (открыть PR → попытаться завершить ход без вотчера →
     хук заблокирует).
6. PR с описанием по нашим же правилам (это первый PR нового процесса —
   он и есть образец).
```

## Критерии готовности

- [ ] `tools/claude/board_status.sh <N> progress` переводит issue на доске
      (и добавляет на доску, если карточки не было).
- [ ] `.claude/settings.json` содержит SessionStart/Stop-хуки
      babysit_guard; `bash -n tools/claude/*.sh` молчит.
- [ ] Скиллы duty/spec/review видны агенту (упоминаются в списке скиллов
      новой сессии).
- [ ] Первый реальный PR: агент открыл PR и НЕ смог завершить ход, пока не
      взвёл вотчер бебиситинга (или не создал `.claude/babysit-paused`).
- [ ] `claude --worktree test` создаёт рабочую копию; сессия в ней видит
      общую память (симлинк создан хуком link_shared_memory).

## Бюджетные развилки

- **Эконом / старт**: можно жить одной сессией без worktrees — весь цикл
  (спека → работа → PR → ревью → мерж) работает и так; worktrees нужны,
  когда захочется параллельности. Всё в этом этапе бесплатно.
- **Как у оригинала**: 2–4 параллельных инстанса (долгоживущие доменные
  worktree `uiux`/`backend` + фичевые), общая память через симлинк,
  janitor для уборки (приедет на этапе 08). Триггер: вы заметили, что
  ждёте одного агента, чтобы дать задачу другому.
- Грабля масштаба: **тяжёлые сборки в двух worktree одновременно не
  гонять** (мобильные сборки съедают всю машину) и **докер-стек данных
  один на всех** — вторые compose-проекты плодят хаос портов.
